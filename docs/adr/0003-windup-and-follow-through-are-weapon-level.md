# Windup and Follow-through live on Weapon, not per-variant

Status: accepted

The weapon-action-feel map set out to give Gun and Magic the same kind of visible action animation Melee_Weapon already had via `swing_time`/`swing_timer` — a per-swing cosmetic timer living on the `Melee_Weapon` variant struct. The obvious first reach was to give Gun and Magic their own equivalent fields the same way: `recoil_time`/`recoil_timer` on Gun, `cast_flourish_time`/`cast_flourish_timer` on Magic, each variant owning its own cosmetic-timer concept, mirroring how `Melee_Weapon` already did it.

We rejected that. Once Windup (the new pre-Resolve telegraph phase) and Follow-through (the post-Resolve cosmetic phase, `swing_time`/`swing_timer`'s generalized successor) were named as domain concepts, their gating logic turned out to be identical across all three variants: which one a weapon shows is decided entirely by `Fire_Mode` (`Semi_Automatic` → Windup, `Automatic` → Follow-through), not by which variant it is. A Sword (Melee_Weapon, Semi_Automatic) Windups; a Dagger (Melee_Weapon, Automatic) shows Follow-through — same variant, opposite behavior. Duplicating near-identical timer pairs into Gun and Magic to re-express logic that's actually a function of `Fire_Mode` alone would mean three copies of the same gating rule, and three places to keep in sync if that rule ever changed.

Instead `windup_fraction`/`windup_timer` and `follow_through_time`/`follow_through_timer` join `kind`/`fire_mode`/`damage`/`action_rate`/`cooldown_timer` as common fields directly on `Weapon`, read and driven the same way regardless of variant. `Melee_Weapon`'s old `swing_time`/`swing_timer` is retired — its post-hit-sweep behavior for Dagger is now just Follow-through, expressed at the `Weapon` level like every other kind's. (`windup_fraction` is a proportion of the cycle rather than a fixed duration in seconds like `follow_through_time` — see ADR-0004 for why.)

This is the same wrapper-struct-vs-bare-union tension ADR-0001 already resolved for `Weapon` as a whole, showing up again one level down: reach for a per-variant field when the behavior is genuinely variant-specific, and a common `Weapon` field when the behavior is actually governed by something orthogonal to variant (here, `Fire_Mode`) and would otherwise be duplicated three times to say the same thing. Consequence: every `Weapon_Kind`'s preset now sets `windup_fraction` or `follow_through_time` (never both) rather than the variant-specific timers the original melee-only design used, and the `Weapon_Variant_Save` persistence DTO no longer needs to carry a Melee-specific swing timer at all — Windup/Follow-through state is transient, frame-driven, and never persisted, the same as `cooldown_timer` already wasn't.
