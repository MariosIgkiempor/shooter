# In-game menus move off vendor/ui to a hand-rolled, no-layout-engine component set

Status: accepted

`vendor/ui` (the shared immediate-mode UI submodule, `layout.odin` + `ui/ui.odin`) stays exactly as-is for `debug.odin`'s F8 panel and `editor.odin`'s level editor, but the six in-game menu screens in `hud.odin` (Splash, Account Progression, Run Start, Map Selection, Run End, Shop) move to a minimal, first-party component set instead: a single `draw_menu_button` helper (positional params matching this codebase's existing hand-rolled drawing helpers, not `vendor/ui`'s `Options`-struct style; hover/press/disabled feedback via plain raylib input, no `vendor/ui` node-tracking), reusing the already-vendor-free `draw_ui_panel`/`draw_text` as-is for panel backgrounds and labels. No generic layout engine replaces `vendor/ui`'s `layout.odin`: screens position their own content via a plain per-screen running `y` cursor (five screens) or, for Shop's tile grid, inline manual row/col math — both documented conventions, not shared procedures, since each is used by more than one screen only in the cursor case and that case is trivial arithmetic. A new first-party `Menu_Theme` constant table replaces `HUD_THEME`'s current use of `vendor/ui`'s `ui.Theme` type, holding only button-state colors, font size, padding, and gap — dropping the window-chrome fields (`title_bar`, `title_text`, `window_background`) `ui.Theme`'s shape forced onto `HUD_THEME` but the hand-rolled screens don't use, since a screen's title is just its own first `draw_text` call.

Considered Options: keeping `vendor/ui` for the menus as today (rejected — the whole point of this effort); a small generic layout engine, still simpler than `vendor/ui`'s but still a reusable flex/grow system (rejected during charting in favor of fully hand-rolled per-screen, since none of the six screens' content is complex enough to need one); a shared "purchasable row" helper bundling name+price+button, despite that shape recurring three times across the six screens (rejected — the three call sites don't actually share one shape closely enough to be worth forcing through a single signature).

See [In-Game Menu UI Overhaul](../../.scratch/ui-overhaul/map.md) and [Component API & styling convention](../../.scratch/ui-overhaul/issues/03-component-api-and-styling.md) for the full spec this settles.
