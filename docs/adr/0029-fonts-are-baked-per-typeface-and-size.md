# Fonts are baked per typeface and size; the atlas builder lives in-tree

Status: accepted. Supersedes the "fixing the font atlas directly" option [ADR-0011](0011-in-game-hud-moves-to-world-space-resource-indicators.md) rejected.

Every piece of text the game drew came from one bake: `data/font.ttf` (Kenney Mini Square, a pixel typeface) rasterised once at nominal 32 into the atlas and exposed as a single global raylib font. Each call site then passed its own size — 10 for HUD counters and damage numbers, 18 for menus, 22 for titles and the F8 panel — and raylib resampled the 32 bake with point filtering. ADR-0011 named the stretched result as the reason to move the in-game HUD into world space and explicitly rejected baking more sizes, on the grounds that nothing else needed it. That stopped being true: menus, the HUD counters that came back into `ui_camera` space, the editor and the debug panel all still drew resampled text, and the editor and F8 panel — dense tool UI — were doing it in a pixel typeface built for eight-pixel capitals.

**Text is drawn only with a `Font`: a typeface baked at one nominal pixel height, generated as a flat enum by the atlas builder from a table of `(typeface, sizes)` it owns.** `fonts/` holds the typefaces by file stem; the builder's `TYPEFACES` table says which sizes each is baked at; `atlas.odin` gains `Font :: enum { Mini_Square_16, Mini_Square_32, Debug_18 }` and one glyph set per entry; `draw_text` and `measure_text` take a `Font` and have no size parameter. A size that is not baked is not expressible. The one place a number still names a size — vendor/ui's theme `font_size` — goes through `font_for_ui_size`, which panics on anything unbaked. Every Font shares one charset, and a typeface that lacks any rune in it is a builder error, so no Font can have a hole another lacks. The game typeface is baked at 16 and 32 because those land on Mini Square's own pixel grid — baking at the 18 and 22 the call sites used would only have moved the blur from raylib into the atlas. The debug typeface is a proportional face the repo's owner supplies, baked at 18, the one size vendor/ui's default theme uses.

The builder itself moves from a git submodule (a fork of karl-zylinski/atlas-builder carrying only config diffs) to a plain in-tree file, beside `vendor/map-builder` which was already in-tree and modelled on it. The `TYPEFACES` table and the generated `Font` enum make the builder game-specific; a submodule bought a two-repo commit for every size added and nothing else.

Considered and rejected: bumping the fork's pinned commit instead of vendoring (kept the two-repo dance for a file that is no longer shared with anyone); a `fonts/fonts.toml` manifest of sizes (a second format to parse for a table that changes a few times a year, and no compile-time check that a listed size matches what code asks for); keeping runtime scaling with bilinear filtering (defeats the pixel typeface entirely and still resamples the debug face); baking exactly the sizes call sites already used (crisp-looking only by accident, and off-grid for a pixel face). The `DAMAGE_NUMBER_FONT_SIZE` Tunable was deleted rather than converted to a `Font` picker — nothing else in the tuning panel chooses fonts, and a live size knob was only ever tuning a resample.

The `ui_camera` (zoom = `window_height / 180`) that the HUD counters and "Editing" label were drawn under is deleted: it resampled 8px glyphs by a fractional factor at any window height not a multiple of 180, which is the same blur this ADR exists to remove, and nothing else used it. Both now draw 1:1 in screen space like every Screen. The charset grew `/()%`, so the "of"/bracket workarounds in the Shop and Main Menu are gone.
