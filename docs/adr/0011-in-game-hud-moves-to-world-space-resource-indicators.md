# In-game resource HUD moves from screen-space bars to world-space Resource indicators above each entity

Status: accepted

The bottom-of-screen HUD (health/ammo/XP bars, `draw_hud`) rendered inside `game.ui_camera`, a virtual low-res camera whose zoom scales with window size — the actual cause of the reported "stretched" HUD font, since text got upscaled well past the single baked 32px font atlas at larger windows. Rather than fixing the atlas or camera, the bottom HUD is replaced entirely by small icon+particle **Resource indicator**s (see CONTEXT.md) drawn above each entity in world-space (`game.camera`, pinned near `GAMEPLAY_ZOOM :: 1.2`), reusing the existing above-enemy health-bar placement pattern — this sidesteps the stretching problem as a side effect, since `draw_health_bar` and damage numbers already prove that camera renders crisply regardless of window size. Every entity (Player, Enemy) shows a Health indicator: an icon beside a flat rect bar (no nine-slice) whose translucent fill is populated by particles contained inside it, tracking the resource fraction via particle count rather than spawn rate. The player additionally shows exactly one weapon-family-keyed secondary indicator — an Ammo indicator for Gun, a Cooldown indicator for Melee_Weapon/Magic, never both, since only one Weapon is ever equipped, and Windup gets no indicator of its own since it's already telegraphed on the weapon's own draw. XP is dropped from the live HUD entirely, since ADR-0009 already made real-time XP collection meaningless; the Run End screen remains XP's only display. Enemies get a smaller fixed particle budget than the player and a red-only color lerp (vs. the player's green-to-red), keeping color a reliable friend/foe signal at up to `MAX_ENEMIES :: 24` concurrent. No indicator anywhere shows a numeric readout — every one is fraction-only, matching what the old bars already communicated.

Considered Options: nine-slice panel art for the bars (rejected — not enough room to render legibly at this size; panels stay a menu-only visual language); a bare icon with particles floating/orbiting/pulsing freely around it, no bar at all (prototyped, rejected live in favor of a bar shape with particles contained inside the fill — the floating version didn't read clearly); fixing the font atlas directly (baking multiple sizes, adding texture filtering) to keep the bottom-screen HUD as-is (rejected — moving to world-space solves the stretching as a side effect without touching the atlas/font system); the shared drag-based `particle.odin` primitives (`spawn_particle_burst` etc.) for the bar-fill effect (rejected — they fly outward and fade, unsuited to particles that must stay contained inside a shrinking rect; the real implementation needs its own small local particle set per bar, with positions stored relative to the bar rather than world-space to avoid the particles visibly reacting to entity movement).

See [In-Game HUD Redesign](../../.scratch/hud-redesign/map.md) and its three tickets for the full spec this settles.
