# Blurred backdrop reuses the panel's own Reveal/Dismiss alpha, gated on "a Screen over a populated world"

Status: accepted

Whenever a Screen (ADR-0014) is showing over a populated game world, `draw_game`'s world-drawing pass now renders through a two-pass separable Gaussian blur plus a flat dim overlay instead of straight to the backbuffer. The new pure proc `blurred_backdrop_strength()` (`hud.odin`) drives both the blur radius and the dim alpha, and returns exactly `menu_element_anim(0, 0).alpha` — the same rank-0 alpha the Screen's own panel fill/border already animate with — whenever `current_screen()` is non-nil *and* `game.current_map.name` is non-empty; `0` otherwise. No new field was added to `Menu_Transition`, and no separate blur timer exists.

Reusing the panel's own alpha rather than introducing a parallel timer means the blur is structurally incapable of drifting out of sync with the panel's Reveal/Dismiss animation — they're the same read, not two computations tuned to match. The trigger condition is "a Screen is currently showing over a populated world" (`current_screen() != nil && current_map.name != ""`), not a hardcoded list of which `Screen_Kind` values should blur. This is deliberate: Shop and Run End are today's only two Screens with a populated world behind them, so this condition already covers exactly those two with no per-`Screen_Kind` branch, and a future overlay menu (e.g. a pause menu, explicitly out of scope here) gets the same blurred backdrop automatically the moment it's implemented as a Screen over `current_screen()`/`current_map`, with no additional wiring required.

Considered Options: a dedicated blur-fade timer, separately tuned to approximate the panel's own Reveal/Dismiss duration (rejected — two independently-tuned timers driving what should look like one continuous effect can only ever approximately match, and any future change to `MENU_THEME.duration` would require remembering to update the blur timer too); a `Screen_Kind`-keyed whitelist (e.g. `case .Shop, .Run_End: blur = true`) explicitly listing which Screens blur (rejected — this is exactly the kind of per-Screen-Kind wiring the "populated world" condition avoids, and would silently need a second edit whenever a future world-backed Screen like a pause menu is added, whereas the chosen condition covers it automatically the moment it starts reading `current_screen()`/`current_map`).

See [menu-backdrop-blur spec](../../.scratch/menu-backdrop-blur/spec.md) and [ADR-0014](0014-menu-ui-flat-rect-and-reveal-dismiss-animation.md) for the Screen/Menu_Transition system this builds on.
