# XP is a Run-end grant spent on permanent Account_Stat, not a real-time Level-up

Status: superseded by [ADR-0016](0016-gold-is-the-single-currency.md), which retired XP entirely - the Run-end grant this ADR designed is now a Gold settle (`bank_run_gold`) of what the Run did not spend.

[ADR-0006](0006-gold-shop-run-progression-xp-account-progression.md) established Gold/Shop as Run-scoped and XP/Level/Class as Account progression, but left XP's actual payoff undesigned: it was still collected in real time via orbs, and leveling up showed a Continue-only popup "reserved for a future Account-progression payoff not yet designed." The [Account Progression Rework](../../.scratch/account-progression/map.md) map designs that payoff.

XP is no longer collected in real time. It's granted once, at Run end (death), as `xp = kills_xp + survival_xp + gold_xp` — kills summed via a per-`Enemy_Kind` `{ base_xp, xp_multiplier }` lookup (extensible for enemy variety that doesn't exist yet), survival time contributing linearly, and Gold earned weighted lower than the other two terms since Gold already partly derives from kills via the existing pickup-drop chance. The old real-time XP-orb pickup and the mid-Run Level-Up/Continue popup both retire. Death now shows a single "Run Ended" screen — replacing the old Game Over screen entirely, not stacking alongside it — that reports the Run's stats and lets the player spend earned XP on `Account_Stat` (see CONTEXT.md) before continuing into the next Run's weapon pick (`ProgramMode.Run_Start`, see [ADR-0008](0008-weapon-family-is-run-scoped.md)). Spending is optional; unspent XP banks indefinitely across Run-ends.

Consequences: `xp_orb.odin`'s real-time collection and `draw_level_up_ui`'s Continue-only popup are retired in favor of the Run End screen (see [Run-start and run-end screens](../../.scratch/account-progression/issues/01-run-start-and-run-end-screens.md)). Level remains only as an XP-threshold display milestone — it grants no purchasing power itself; purchasing power lives entirely in `Account_Stat`, priced on `Upgrade_Preset`'s geometric mechanism but with gentler growth and no `max_stack` cap (see [XP formula and Account_Stat pricing](../../.scratch/account-progression/issues/02-xp-formula-and-account-stat-pricing.md)). `data/game_save.json` drops `Player.class`/`class_chosen` with no migration path (see [Save-data and program-mode flow](../../.scratch/account-progression/issues/03-save-data-and-program-mode-flow.md)).
