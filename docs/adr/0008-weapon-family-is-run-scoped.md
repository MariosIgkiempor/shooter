# Weapon family is Run-scoped, not a permanent Class lock

Status: accepted

[ADR-0002](0002-class-locked-weapon-acquisition.md) locked weapon acquisition to a permanent Class, chosen once at game start. The [Account Progression Rework](../../.scratch/account-progression/map.md) map moves character progression into persistent stats earned via XP instead, which makes a permanently locked weapon family redundant — so that lock is retired.

Weapon family (`Ranged`/`Melee`/`Magic`, renamed from Class) becomes purely Run-scoped: derived from whichever `Weapon` is currently equipped, not stored as a persistent `Player` field. The player picks a fresh starting weapon — any of the 8 across all three families — at the start of every Run, replacing `ProgramMode.Choosing_Class` with `ProgramMode.Run_Start`, entered uniformly at first app launch and after every death. This removes the old asymmetry where Class was gated once-ever but the Map picker (`Selecting`) already re-ran every launch — both now repeat identically every Run. The Weapon tier ladder and family-specific Shop Upgrade slots (Clip Size/Arc Width/Range) keep working exactly as before — same mechanism, same fixed sequential per-family order — just gated on the equipped weapon's family instead of a persistent `player.class` field.

Consequences: `Class` the type renames to `Weapon_Family`; `Player.class`/`Player.class_chosen` fields retire entirely, with no migration path (see [Save-data and program-mode flow](../../.scratch/account-progression/issues/03-save-data-and-program-mode-flow.md) — this is unshipped software, no external saves to preserve). `Upgrade_Preset.class: Maybe(Class)` becomes `Upgrade_Preset.family: Maybe(Weapon_Family)`, checked against the currently equipped weapon rather than a persistent field. `draw_class_selection_ui` is replaced by a weapon picker on the new `Run_Start` screen (see [Run-start and run-end screens](../../.scratch/account-progression/issues/01-run-start-and-run-end-screens.md)). The old Game Over screen (`draw_game_over_ui`, its "Restart" button) is retired too — death now leads into the Run End screen (see [ADR-0009](0009-xp-is-a-run-end-grant.md)), which leads into `Run_Start`.

## Amendment: the free pick is tier 0, not any of the eight

Recorded while resolving [Weapon catalog expansion](../../.scratch/content-expansion/issues/08-weapon-catalog-expansion.md).

"The player picks a fresh starting weapon — any of the 8 across all three families" was written to describe the *replacement* for the retired Class lock, and the phrase "any of the 8" rode along unexamined. It does not survive contact with the tier ladder this same ADR promised would "keep working exactly as before": `weapon_family_kinds` is read both as the Shop's priced ladder and as the Run_Start menu, so picking Shotgun cost 0 Gold, arrived at Ranged tier 2 and left `weapon_next_tier` returning nil — the Shop's weapon slot dead for the whole Run — while picking Pistol cost 390 Gold to reach the same place. `shop.odin` already asserted the opposite of the ADR in its own comment: "tier 0 is always the family's starting weapon, equipped for free when picked on the Run_Start screen, never purchased." At twelve weapons the free menu would have been twelve buttons, four of them the paid destinations of the other eight.

**Run_Start offers tier 0 only — one weapon per family.** Everything this ADR actually argued for is untouched: Weapon family stays Run-scoped, derived from the equipped weapon, re-picked every Run, with nothing on `Player` storing it. Only the free skip up the ladder goes.
