# Content-scale integration sweep

Type: grilling
Blocked by: 01, 02, 03, 05, 12
Status: resolved

## Question

What breaks once the catalogs are real rather than placeholders?

Every system in this game was built and tested against one enemy kind, one map, and eight weapons. This ticket walks the seams and decides what each needs, producing an implementation checklist rather than leaving the follow-on session to discover them — the same shape [Enemy behaviours](../../enemy-behaviours/map.md) used for its editor/persistence tickets.

Known seams:

- **`ENEMY_MAX_HEALTH` is deleted.** `Enemy` gains `max_health` from its preset; the two draw-time reads ([main.odin:1095-1096](../../../main.odin)) and `enemy_body_size`'s caller switch to it. Worth checking what else assumed a uniform 50 — `enemy_spawn_test.odin` and the debug overlays are the likely sites.
- **`MAX_ENEMIES :: 24`.** A composition batch is silently truncated at the cap, which is precisely why [ADR-0017](../../../docs/adr/0017-run-outcome-and-map-objective.md) derives Cleared from the timeline rather than a kill quota. A deeper roster, denser ladder rungs, and a boss spawning adds all press on this ceiling from different directions. [Map ladder shape](03-map-ladder-shape.md) named the concrete case: **rung 4 ("Ring")** is authored as swarm density at peak trigger overlap, so it is the rung that hits the cap first, and rung 5 needs slots left over for a boss alongside its adds. Raise it, budget it per rung, or prioritise which enemies survive truncation?

  **Settled by [Enemy catalog](04-enemy-catalog.md): the cap rises to 4096 and stops being a design input.** It becomes a safety rail against a runaway `Repeating` trigger, not a budget the ladder is authored against — rung 4 is authored at 150-250 concurrent, set by screen legibility rather than by an array bound. Nothing on this seam is left to decide here; what actually binds at that scale moved to [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md). Note two arguments elsewhere on this map rested on the old ceiling and no longer do: [Elite and affix tier](10-elite-and-affix-tier.md)'s "at the cap, more pressure can only mean heavier bodies" (the Breaker keeps its place on the Tell-carrier argument, which never depended on it), and the reserved boss slot below.
- **`MAX_SEARCH_NODES :: 1024` is too small for the map that already exists.** A BFS across `desert_dungeon`'s 2592 cells can't complete, so `find_path` returns not-ok, `enemy.path` empties, and `chase_to` falls back to `target = goal_world` — a straight-line chase into walls whenever an enemy is far from the player ([enemy.odin](../../../enemy.odin)). This is a live bug independent of any content decision, surfaced by [Map layout authoring model](02-map-layout-authoring-model.md). Raise the cap (it costs per-enemy-per-frame, up to `MAX_ENEMIES` times), compute one flow field per frame from the player instead of a path per enemy, or cache paths across frames. It is also the reason map footprint is held flat, so leaving it broken quietly caps the ladder.

  **Moved to [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md).** [Enemy catalog](04-enemy-catalog.md) authored rung 4 at 150-250 concurrent bodies, which turns this from a live bug into the deciding constraint on the whole movement architecture — too large to settle as one line on a sweep checklist, and it is the roster's precondition rather than a follow-on to it.
- **`Tile.atlas_coords` is deleted** ([ADR-0021](../../../docs/adr/0021-map-layouts-are-hand-authored-places.md)), which touches four places at once: `Tile` in [main.odin](../../../main.odin), the mirror `Tile` in [map_builder.odin](../../../vendor/map-builder/map_builder.odin), all 1704 baked literals in `maps.odin` (regenerated, so free), and `desert_dungeon.json` (~123 KB, roughly halves). The editor's Tiles mode loses `TILESET_COLS`/`TILESET_ROWS`, `Palette_Cell`, `editor.selected_tile` and the palette draw at [editor.odin:389](../../../editor.odin), collapsing to a wall/floor toggle. `tileset_normal` stays generated in `atlas.odin` with no consumer — deliberately, see the ADR.
- **The editor grows map-level authoring** it has none of today: a "New map" button writing a stub file, plus `name`, click-to-place `player_start`, and `time_limit` / `victory_multiplier` fields. Save currently writes tiles and triggers only ([editor.odin:439](../../../editor.odin)). Note the inherent bake round-trip — a new file has no `Map_Name` case until the next build.
- **Map validity gains a test** over the baked `maps` table: per `Map_Name`, one connected walkable region, `player_start` on floor, a reachable off-screen spawn ring, and a cell-extent bound (footprint is conventional, not a field on `Tilemap`).
- **`Map` gains a `rung: int`** ([ADR-0022](../../../docs/adr/0022-map-rungs-are-gated-by-clears.md)), which rides the same four-place path `atlas_coords`'s deletion does in reverse: `Map` in [map.odin](../../../map.odin), the mirror in [map_builder.odin](../../../vendor/map-builder/map_builder.odin), the baked literals, and `desert_dungeon.json`. It joins `time_limit`/`victory_multiplier` in the editor's new map-level panel, and the map-validity test above gains "rungs are 1..N, no gaps, no duplicates".
- **The Account gains a persisted cleared set.** One bool per Map, Account-scoped, surviving `start_new_run` alongside `gold`/`banked_progress`/`level`/`account_stat_stacks`/`relic_stacks`, written by `end_run` on `.Cleared`. **Keyed by identity string, not enum ordinal** — `map_builder` sorts `Map_Name` by filename ([map_builder.odin:165](../../../vendor/map-builder/map_builder.odin)), so adding a map file renumbers every case after it and an ordinal-keyed set would silently credit or revoke clears. Reuse `map_identity_string`, the mechanism `active_map_pointer` already uses. Note this is the first Player field whose shape differs from `account_stat_stacks`' enum-keyed array, so the save-file precedent is deliberately not followed here.
- **Map Selection is reworked, not just re-styled.** `draw_map_selection_ui` ([hud.odin](../../../hud.odin)) draws one unconditional button per `Map_Name` in a single column. It must sort by `rung` and convey locked/unlocked and cleared/not, plus `time_limit` and `victory_multiplier`, and draw locked rungs rather than hiding them (`account_stat_unlocked`'s precedent). Five rows still fit the existing column, so this is an information change, not a layout redesign. It also needs a locked-state icon — `icon.odin` has no lock glyph today.
- **`time_limit` becomes derived, not eyeballed.** Per [ADR-0022](../../../docs/adr/0022-map-rungs-are-gated-by-clears.md) it is `timeline_end + slack`, and a limit below the timeline's natural end makes a rung unwinnable rather than hard. Worth a validity check alongside the connectivity one: for every Map, `time_limit` exceeds the point its last Spawn Trigger can still be spawning.
- **Persistence — now a deletion, not an extension.** [Enemy variety model](01-enemy-variety-model.md) found `Spawn_Composition_Entry` to be the only place enemy unions are ever marshalled, so authoring an `Enemy_Kind` there removes them from persistence entirely: `Movement_Style_Save`/`Attack_Style_Save`, their four conversion procs, `map.odin`'s hooks ([map.odin:59-76](../../../map.odin)), and `vendor/map-builder`'s duplicated DTOs and both `write_*_literal` procs ([map_builder.odin:326](../../../vendor/map-builder/map_builder.odin)) all become dead. `desert_dungeon.json`'s six composition entries need rewriting as `(kind, count)` — which also stops it baking runtime fields (`attack_timer`, `wobble_phase`) into the file. New axis variants therefore need **no** `*_Save` mirror. `Spawn_Trigger`'s own condition/mode unions are untouched and still need theirs — the `core:encoding/json` union-guessing hazard is real and confirmed here ([enemy.odin](../../../enemy.odin)), just no longer on the enemy path.
- **The level editor.** Settled by [Enemy variety model](01-enemy-variety-model.md), and in the opposite direction to what this ticket first assumed: `draw_spawn_composition_entry_ui` **collapses** to a kind selector plus a count, losing every per-field slider ([editor.odin:694](../../../editor.odin)). Since presets are a code table, numeric tuning now means editing `enemy.odin` and rebuilding — the `weapon_presets` model. Open here: whether a debug-panel live-tuning overlay is worth building to replace what the sliders gave (`debug.odin` is toggles and buttons only today, so there is no idiom to extend), or whether rebuild-to-tune is genuinely fine.
- **`enemy_gold_presets` is dissolved, not filled.** [Enemy variety model](01-enemy-variety-model.md) folded the Gold payout into `Enemy_Preset`, so there is one table keyed by `Enemy_Kind` rather than two. `enemy_gold_value` reads through it; `total_kills` and the `[Enemy_Kind]int` kill tally are unaffected but now iterate a real roster.
- **The dev weapon-cycle hotkey.** `cycle_weapon_kind` walks `weapon_family_kinds` with the arrow keys, and [Shop and upgrades](../../shop-and-upgrades/map.md) already carries "whether the dev-only LEFT/RIGHT hotkey is retired now a real Shop exists" as open fog. A longer ladder makes it either more useful or more misleading.
- **Debug overlays.** `draw_debug_attack_ranges` and the Movement Style visualisation assume today's small vocabulary.

- **The boss needs a reserved `MAX_ENEMIES` slot.** `fire_spawn_composition` `return`s outright once the cap is reached ([enemy.odin:601](../../../enemy.odin)), so an add trigger firing into a full field can drop the boss's own spawn entirely — and a rung whose boss never spawned clears the moment its timeline runs dry, silently. [Boss model](05-boss-model.md) put the boss on its own `One_Shot` at `Time_Elapsed{0}`, which makes the ordering safe in practice, but the reservation is what makes it safe by construction.

  **Moot, per [Enemy catalog](04-enemy-catalog.md).** With the cap at 4096 the field is never full, so there is nothing to reserve against.
- **Path inflation becomes size-derived, and the boss gets its own collision map.** `update_enemies` paths every enemy against `build_inflated_collision_map(tilemap, 1)` ([enemy.odin:878](../../../enemy.odin)) — one tile of clearance against 16x16 tiles, sized for the 3-tile body today's clamp allows. A boss past that is handed BFS paths through gaps it cannot enter and jams against `move_actor` while the path keeps insisting; `find_path` is cell-based with no notion of body width. With exactly one boss, a second collision map per frame is cheap. A boss too wide for a corridor simply not entering it is accepted, not a bug.
- **`ENEMY_SIZE_MAX :: 48.0` rises** ([main.odin:841](../../../main.odin)) with the `10 + 0.28 x max_health` derivation untouched, so size still means health and nothing becomes independently authorable ([ADR-0020](../../../docs/adr/0020-enemy-kind-is-the-authored-unit.md)). The clamp is reached at 136 health today, so this touches exactly one entity — but it is the constant that decides whether the boss can look like one.
- **The Resource indicator comes back for one entity.** `draw_player_resource_indicators` is the only indicator path today; commit `665ad38` deleted the enemy one and left `draw_enemy`'s opacity fade in its place ([main.odin:1094](../../../main.odin)). The boss needs the world-space fraction-only Health indicator restored ([ADR-0011](../../../docs/adr/0011-in-game-hud-moves-to-world-space-resource-indicators.md)'s no-screen-space-bars rule is untouched — the exception is which entities carry one). Note the particle budget: `PLAYER_BAR_MAX_PARTICLES :: 20` was sized for one entity, and the boss adds a second live bar.
- **Boss death bypasses the drop roll.** `maybe_spawn_pickup` rolls `PICKUP_DROP_CHANCE :: 0.25` then picks uniformly among three kinds ([pickup.odin](../../../pickup.odin)), so a boss would pay Gold about one kill in twelve. It needs a guaranteed Gold drop priced from its preset, which means `apply_hit_to_enemy`'s death path gains a branch rather than `maybe_spawn_pickup` gaining a parameter — worth deciding which, since the same shape will be wanted by any future guaranteed drop.
- **A Tell needs a floor draw layer.** [Boss telegraph and phase feel](06-boss-telegraph-and-phase-feel.md) settled that a Tell's claimed area is drawn *on the ground* — under every actor, over the tilemap. `draw_world_contents` ([main.odin](../../../main.odin)) has no such layer: it draws the tilemap, then enemies, then the player, and the only existing world-space area (`draw_poison_clouds`) is drawn late, *over* actors, which is wrong for something the player has to stand out of. One insertion point straight after `draw_tilemap`, but worth deciding whether poison clouds move there too rather than leaving two conventions for "an area on the ground". [Per-map theming and ambient effects](07-per-map-theming-and-ambient-effects.md) puts a **second** thing on that layer — a Map theme's floor patches — so the insertion point now has two independent consumers and is worth naming as a layer rather than adding twice.
- **Recovery is authored per phase, not just per kind.** Phase legibility rests on pacing tightening across thresholds ([Boss telegraph and phase feel](06-boss-telegraph-and-phase-feel.md)), so the per-phase recovery figure is load-bearing for the read, not only for difficulty — it cannot be collapsed into a single per-kind cooldown during balance passes.
- **A Tell needs runtime state on `Enemy`.** [ADR-0023](../../../docs/adr/0023-enemy-tells-are-absolute-durations.md)'s Tell is a countdown in seconds plus the committed action it resolves into, and phases add a threshold index. Both are runtime, so they follow `attack_timer`/`wobble_phase`'s precedent — on the spawned `Enemy`, never on the preset, and never persisted. Since [Enemy variety model](01-enemy-variety-model.md) removed enemy unions from persistence entirely, the new `Attack_Style` variant needs **no** `*_Save` mirror. Note the variant's *authored* side is a slice of *(attack, tell seconds)* pairs per phase, not scalars ([Boss telegraph and phase feel](06-boss-telegraph-and-phase-feel.md)), so `Enemy_Preset` gains its first non-scalar field — check what that costs the preset table's literal form.

- **`Map` grows three theming fields** ([ADR-0024](../../../docs/adr/0024-a-map-owns-its-visual-identity.md)): a floor colour, a wall colour, and the ambient-effect set. Same four-place path `rung` takes — `Map` in [map.odin](../../../map.odin), the mirror in [map_builder.odin](../../../vendor/map-builder/map_builder.odin), the baked literals, and `desert_dungeon.json` — plus six `ui.slider` rows on the editor's new map-level panel. It also **deletes `map_icon_colors`** ([map.odin](../../../map.odin)) and its one consumer at [hud.odin:1039](../../../hud.odin), which now reads the chosen Map's wall colour; `icon_swatch`'s "placeholder vocabulary, worth replacing at map two" note ([icon.odin](../../../icon.odin)) resolves at the same time. The map-validity test gains "floor and wall colours are non-zero" — a fully transparent Map is exactly the failure the deleted code-side table would have shipped silently.
- **`draw_tilemap` culls nothing.** It loops all 1704 of `desert_dungeon`'s tiles every frame against roughly 225 actually visible (`tile_size` 16 into the 320x180 world view `PIXEL_WINDOW_HEIGHT` gives), and `draw_blurred_world` runs the whole of `draw_world_contents` a second time into an offscreen texture whenever a menu is open. Harmless at one map and no ambience; worth deciding now that a floor decal layer and a mote layer sit on top of it, and that the standing "unmeasured per-frame transform cost at scale" fog item points here.
- **Ambient effects need their own pool and two z-slots.** Not `game.particles` ([ADR-0024](../../../docs/adr/0024-a-map-owns-its-visual-identity.md)) — that is unbounded, event-driven, cleared by `reset_particles` at a Run boundary, and drawn in one fixed slot between pickups and damage numbers. Motes draw in front of actors and floor patches behind them, so the ambient layer is two insertion points in `draw_world_contents`, not one.
- **The light wash is screen-space, and the blurred backdrop is too.** A Map theme's directional wash draws after `end_using_camera`, which puts it *over* `draw_blurred_world`'s blur-and-dim composite whenever a menu is open ([ADR-0015](../../../docs/adr/0015-blurred-backdrop-reuses-panel-reveal-dismiss-alpha.md)) — an un-blurred tint on a blurred world. Decide whether the wash belongs inside `draw_world_contents`' offscreen pass (so it blurs with everything else) or is suppressed while a Screen is up.

- **Raising `ENEMY_SIZE_MAX` for the boss hands the whole roster headroom.** The clamp is global and the derivation is shared, so once it rises, any preset authored past 136 health grows past the 3-tile body that `update_enemies`' single shared `build_inflated_collision_map(tilemap, 1)` ([enemy.odin:708](../../../enemy.odin)) is sized for. [Elite and affix tier](10-elite-and-affix-tier.md) held heavy kinds at or below the old 48px as an **authoring rule in the catalog**, not a second clamp — worth deciding here whether that stays a convention or the map-validity test grows a "no non-boss preset exceeds the shared inflation envelope" check. The boss's own second collision map is affordable at exactly one boss; the cost is per distinct oversized body, and several at once is a different bill.

- **`Enemy_Kind` persists by name, not ordinal — and `desert_dungeon.json` needs migrating.** [Enemy catalog](04-enemy-catalog.md) amended [ADR-0020](../../../docs/adr/0020-enemy-kind-is-the-authored-unit.md): a composition entry writes its kind as a string, since an enum marshals as its ordinal and inserting a kind mid-enum would silently renumber every composition in every map file. Same mechanism `active_map_pointer` and the Account's cleared set already use (`map_identity_string`), now a third site — worth deciding whether the string-keyed-enum round trip becomes one shared helper rather than three hand-rolled switches. The migration itself is six composition entries in one file, and it lands in the same rewrite that converts them to `(kind, count)`.
- **The enemy palette is five constants, not three.** [Enemy catalog](04-enemy-catalog.md) repalettes to evenly-spaced hues — Grounded green, Swarmer yellow, Floater violet, Charger red, Inert cyan — replacing `ENEMY_GROUNDED_COLOR`/`ENEMY_FLOATER_COLOR`/`ENEMY_SWARMER_COLOR` ([main.odin:828](../../../main.odin)). But [ADR-0020](../../../docs/adr/0020-enemy-kind-is-the-authored-unit.md) made colour a **per-kind preset field**, so `enemy_body_color`'s `Movement_Style_Kind` switch disappears entirely and these become the catalog's authoring reference rather than live constants. Decide whether they survive as named colours at all, or only as a comment beside `enemy_presets`. The debug Movement Style visualisation reads the switch today.
- **`Melee.attack_range` must be authored per kind.** It is measured centre-to-centre ([enemy.odin:751](../../../enemy.odin)), so the current uniform `10` is unreachable for any body wider than ~20px: a 46px enemy cannot touch a 24px player standing against it. [Enemy catalog](04-enemy-catalog.md)'s rule is `attack_range >= body_size/2 + 12`. Since body size derives from `max_health`, this is a relationship between two preset fields that nothing checks — a candidate for the map-validity test alongside the inflation-envelope check below, or for a `#assert`-style guard over the preset table.
- **`ENEMY_SIZE_MAX` rises to ~72, not just "above 48".** [Enemy catalog](04-enemy-catalog.md) authored the Warden at ~220 health, which is what fixes the number.
- **Pickup and draw cost at 10x body count.** `maybe_spawn_pickup` rolls per death, so a 200-body wave leaves ~17 pickups on the ground at once, and `draw_enemy` runs per body. Both were sized against 24. The standing "unmeasured per-frame transform cost at scale" fog item points here as well as at `draw_tilemap`.
- **Gold payout collapses to one `int`.** [Enemy catalog](04-enemy-catalog.md) settled that `base_gold` x `gold_multiplier` becomes a single `gold` field, since only the product is ever read ([account_progression.odin:27](../../../account_progression.odin)). Folds into the same `Enemy_Preset` rewrite that dissolves `enemy_gold_presets` above.

- **The Run_Start screen collapses from eight buttons to three.** [Weapon catalog expansion](08-weapon-catalog-expansion.md) settled that only tier 0 of each family is a free pick, so `draw_run_start_ui`'s inner `for kind in weapon_family_kinds[family]` loop ([hud.odin:980](../../../hud.odin)) becomes a single button per column. Its layout maths derives panel height from `max_kinds` across families, which is about to be 4 rather than 3 while the rendered count drops to 1 — worth deciding whether three columns survive at all once each holds one button. [ADR-0008](../../../docs/adr/0008-weapon-family-is-run-scoped.md) is amended by that ticket.
- **`weapon_family_kinds` stops being read two ways.** It is simultaneously the Shop's priced ladder ([shop.odin:12](../../../shop.odin)) and the Run_Start menu, and [weapon.odin:824](../../../weapon.odin)'s comment asserts the opposite — "only a cycle order for that debug tool, not the Shop's priced tier ladder". The comment is simply wrong today. Decide whether one table with an accurate comment is enough, or whether the ladder and the debug cycle order want separating now that they mean different things.
- **`Melee_Weapon` loses `arc_degrees` and the hit test moves off `enemy_in_melee_arc`.** [Weapon hit volumes](12-weapon-hit-volumes.md) owns the mechanic; the seam is that `Melee_Weapon` is embedded in `Weapon_Variant_Save` and rides into `data/game_save.json`, `apply_upgrades` reads the field for the Melee family Upgrade, and `cast_flamethrower_tick` ([weapon.odin:792](../../../weapon.odin)) constructs a `Melee_Weapon` literal purely to borrow the arc check. Three call sites, one save shape, one Upgrade.
- **`Upgrade_Kind.Clip_Size` changes effect shape, and `Arc_Width` changes meaning.** Clip_Size becomes `Multiplicative` ([Weapon catalog expansion](08-weapon-catalog-expansion.md)) — it is the only Additive Upgrade whose base varies fivefold across the weapons it gates, so today ten stacks are +67% on the SMG and +333% on the Shotgun. Arc_Width now scales the melee weapon's size rather than a deleted arc field, so its enum name and `display_name` both describe something that no longer exists. Both amend [Shop and upgrades](../../shop-and-upgrades/map.md)'s [Upgrade catalog contents](../../shop-and-upgrades/issues/01-upgrade-catalog-contents.md), which left prices and caps as fog but locked effect shape.
- **The Ammo pickup is a no-op occupying a third of every drop roll.** `WEAPON_STARTING_RESERVE_CLIPS :: 69420` ([weapon.odin:380](../../../weapon.odin)) means `refill_weapon_reserve` refills a reserve that never depletes, and `maybe_spawn_pickup` picks uniformly among three kinds after its 0.25 roll ([pickup.odin:60](../../../pickup.odin)). At 150-250 bodies this litters the floor with collectibles that do nothing. Decide between retiring `Pickup_Kind.Ammo` — which meets this map's standing "new pickup kinds" fog item from the other direction — reweighting the roll, or giving reserve ammo a real depletion, the last being the option [Weapon catalog expansion](08-weapon-catalog-expansion.md) explicitly ruled against.
- **Twelve weapons means twelve icons and twelve `Weapon_Visual` rows**, plus a redraw of `icon_poison_staff`: it and `icon_flame_staff` are countably identical today ([icon.odin:316](../../../icon.odin), [icon.odin:325](../../../icon.odin)), separated only by colour, which [ADR-0018](../../../docs/adr/0018-weapon-visual-identity-is-per-kind-not-per-family.md) rules out. Note `weapon_visuals`' Ranged row varies only `length` 30/34/38 across three kinds — the same proportional-not-countable trap at world scale rather than icon scale.
- **`Bullet` gains an id and `Enemy` gains `last_hit_bullet_id`.** [Weapon catalog expansion](08-weapon-catalog-expansion.md)'s pierce mechanism, chosen because index and position memory are both unsafe against `unordered_remove` at swarm density. Both are transient per-frame state, so neither is persisted; the monotonic counter needs somewhere to live and to reset at a Run boundary alongside `reset_bullets`.
- **`Spell_Kind` grows a hitscan variant.** The Lightning Staff resolves instantly along `aim_dir` against the nearest body — the first weapon in the game that spawns neither a travelling `Bullet` nor a lingering entity, so `try_cast_magic`'s "any effect that needs to persist beyond this frame spawns its own tracked entity" convention has nothing to spawn, and a beam that exists for one frame needs a draw path of its own.

- **`move_actor` is the largest per-enemy cost left, and it is not pathing.** It loops the whole `tilemap.tiles` slice once per axis, per actor, per frame ([main.odin:503](../../../main.odin)) — **852,000 `CheckCollisionRecs` calls a frame at 250 enemies** against 1704 tiles. [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md) settled that the flow field's cell-indexed solid set fixes it (test the ~9 cells the box overlaps, ~4,500 checks), and that the player takes the same fix. `tile_blocks_point` ([enemy.odin:660](../../../enemy.odin)) has the identical shape per spawn candidate, and `build_inflated_collision_map` ([enemy.odin:708](../../../enemy.odin)) rebuilds 353x9 hash writes every frame for a tilemap that cannot change mid-Run — it becomes a per-Run build, keyed by inflation radius. Four call sites, one shared structure; decide whether that structure lives on `Tilemap` or beside the field.
- **The one authored map has 888 untiled cells, and they are walkable.** `does_cell_collide` reads `false` for an absent cell, so Desert Dungeon's doorways — and `player_start` at cell `(29,15)` — are *absence* rather than floor, drawing as the `0x181818` clear colour ([main.odin:916](../../../main.odin)) rather than `TILEMAP_FLOOR_COLOR`. 648 cells reachable from the start lie outside the authored 54x48 rectangle entirely. [Map layout authoring model](02-map-layout-authoring-model.md)'s validity test already specifies `player_start` on floor and a cell-extent bound, so this needs no new rule — but Desert Dungeon **fails that test today**, so the sweep decides whether it is patched in place or waits for its redraw as a rung.
- **Deleting the pathfinder touches five files.** `find_path`, `Path`, `MAX_SEARCH_NODES`, `get_neighbours`/`does_cell_collide`, `chase_to`, `assign_swarmer_slots`, `swarmer_surround_radius` and `SWARMER_RING_ROTATION_SPEED`'s slot-ring use all go from [enemy.odin](../../../enemy.odin); `Enemy.path` goes from the struct; [bullet.odin:177](../../../bullet.odin)'s `delete(enemy.path)` on death goes; `draw_path` goes from [main.odin:1132](../../../main.odin); and `Debug_Visualizer.Pathfinding` keeps its name, `display_name` and toggle while drawing something entirely different. Check whether any test file references the removed procs.
- **`movement_goal_point` splits rather than shrinks.** [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md) settled that a colliding style's `Ranged` retreat is a step to the highest-distance neighbouring cell while `Floater` keeps the euclidean straight-line retreat — so the one proc that today serves every Movement Style becomes two paths keyed on whether the style collides. That is the same seam `update_enemies` already branches on for `move_actor` ([enemy.odin:779](../../../enemy.odin)); decide whether the two branches unify into one "does this style collide" predicate rather than being tested twice.
- **Spawn placement gains a reachability test.** `pick_offscreen_spawn_point`'s retry loop checks visibility and wall-blocking but never reachability, so a candidate in a disconnected pocket spawns an enemy that holds [ADR-0017](../../../docs/adr/0017-run-outcome-and-map-objective.md)'s Cleared open forever. The field's filled set is the reachable set, so the check is one lookup — but it needs the field to exist at spawn time, including for the first trigger at t=0, which is a build-order question between `start_new_run` and the first `update_enemies`.
- **Separation's neighbour cap needs a name and a number.** [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md) settled ~8 sampled neighbours instead of the full bucket scan, since the result is a normalized direction. `SEPARATION_GRID_CELL_SIZE :: 40` is sized to Grounded's radius and stays; what is new is a cap constant beside `SEPARATION_RADIUS`/`SEPARATION_STRENGTH`, and a decision on whether the sample is simply the first N encountered or the nearest N.

- **`follow_through_time` stops being cosmetic and `draw_weapon` stops deriving the swing window.** [Weapon hit volumes](12-weapon-hit-volumes.md) settled that a melee weapon's hit volume is live for exactly the Follow-through, carried by **both** fire modes — so `time_since_resolve := (cycle - windup_duration) - cooldown_timer` ([main.odin:1246](../../../main.odin)) is deleted and the renderer reads the same timer the hit-check does. The seam is documentation as much as code: `weapon.odin:57-72`'s field comment, `CONTEXT.md`'s **Windup**/**Follow-through**/**Fire mode**/**Weapon readiness** entries and `weapon_test.odin`'s Follow-through assertions all state the retired "exactly one of these two pairs is ever nonzero" rule. A Sword now sets both.
- **The hit-volume table needs a home and a test.** A parallel `[Weapon_Kind]` table of unit-space polygons beside `weapon_icons`, on the `weapon_icon_reach` precedent, with an assertion that each polygon lies inside what its glyph draws — `icon_test.odin` already holds the equivalent check for the reach table. Decide whether it lives in `icon.odin` with the geometry it mirrors or in `weapon.odin` with the gameplay that reads it.
- **`Enemy` gains a second id field and a second monotonic counter.** [Weapon catalog expansion](08-weapon-catalog-expansion.md)'s pierce and this ticket's once-per-swing rule deliberately do **not** share an id space, so `last_hit_bullet_id` gets a sibling and both counters need resetting at the Run boundary alongside `reset_bullets`. Two counters is the decision, not an oversight — record it where a future reader will otherwise merge them.
- **`Weapon_Visual` gains the swing arc and its own comment goes stale.** The struct is documented as the per-kind *art* record and `weapon_visual_scale`'s comment says melee is excluded because scaling a blade "would decouple its drawn length from the reach it is reporting" — after this the two are one quantity, so the exclusion stands for the opposite reason (the slider would be a live reach cheat) and the sentence as written reads as licence to include melee.
- **Melee `range` values need re-tuning, not renaming.** The volume moves from the feet anchor to the chest pivot, 12px up, so every melee weapon's effective reach against a body's top edge changes. `weapon_world_frame_size` and `weapon_muzzle_position` already key off the pivot; the hit-check joining them is what makes `origin` unused on the melee path, retiring `resolve_weapon_action`'s "hit-checks below keep using `origin`, so reach is unchanged" comment ([weapon.odin:551](../../../weapon.odin)).

Blocked by [Enemy variety model](01-enemy-variety-model.md), [Map layout authoring model](02-map-layout-authoring-model.md), [Map ladder shape](03-map-ladder-shape.md), [Boss model](05-boss-model.md) and [Weapon hit volumes](12-weapon-hit-volumes.md) — it can only sweep seams once it knows what is coming through them. **Every one of those is now resolved**, along with [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md), and their seams are above: this is the last ticket on the map.

## Answer

**Almost nothing breaks that the upstream tickets didn't already break on purpose — what breaks is the order you land them in.** The sweep's twenty-odd seams turned out to be mostly settled work needing writing down; the dozen live questions are closed below, four seam descriptions were wrong about the code, and the deliverable is a dependency-ordered checklist rather than a per-system list, because the concrete failure mode is landing the nine-kind roster before the flow field and concluding the roster is too big.

### Four seams described the wrong thing

- **The Movement Style visualiser does not read `enemy_body_color`'s switch.** `draw_debug_movement_styles` ([main.odin:1336](../../../main.odin)) draws `SEPARATION_RADIUS[kind]` rings in a fixed `rl.PURPLE` plus a `swarmer_surround_radius` ring. So the palette has no debug consumer — but the visualiser breaks anyway, because [Enemy pathing at swarm scale](11-enemy-pathing-at-swarm-scale.md) deletes `swarmer_surround_radius`.
- **The proportional-not-countable trap is on the Magic row, not Ranged.** `weapon_visuals` gives Ranged `muzzle_streak_count` 3/4/7, genuinely countable. Magic is where all three share `streak_count = 0` and differ only by `length` 30/34/32 and `flash_radius` 13/9/15 — two proportional dials, one unordered — and a fourth Magic weapon is coming.
- **`start_new_run` cannot build the flow field.** It fires from `draw_run_start_ui` *before* `request_screen_change(.Map_Selection)` and never touches `current_map`, so the seam's stated build-order choice contains no point where both a Run and a Map exist.
- **`debug.odin` is not "toggles and buttons only".** It already runs a `ui.slider` for `weapon_visual_scale` — but the tuning surface that actually matters is the editor's, `draw_spawn_composition_entry_ui`'s per-field sliders, and it is this sweep that deletes them.

Also: `ENEMY_GROUNDED_COLOR :: rl.RED` while the catalog gives Grounded *green* and red to Charger. Two of the three existing constants invert rather than merely going stale, so the repalette and the preset rewrite have to land in one commit or the roster reads wrong for a build.

### Decided here

**The ground layer is defined by whose information it carries.** A named slot straight after `draw_tilemap` holds floor patches and Tell zones; poison clouds stay above the actors. The distinction is not "lies flat" but *whose output it is* — a Tell and a floor patch are the world telling the player something, a poison cloud is feedback on a shot the player already fired. Ambient effects already carry the rule that they hold no information and may never occlude; the poison cloud is its exact inverse. New glossary entry.

**The light wash draws inside `draw_world_contents`, as a world-space quad over `camera_visible_world_rect`.** Suppressing it while a Screen is up makes the world change colour as a menu opens, which is worse than the un-blurred tint it fixes. In world space it blurs and dims with everything else and needs no knowledge of Screens at all.

**The boss's guaranteed drop is a preset field, not a call-site branch or a parameter.** `maybe_spawn_pickup` already receives the dying `Enemy_Kind` and reads the preset through `enemy_gold_value` — the seam's two options both predate that. Reading the guarantee where the payout is already read means no second death path for a future guaranteed drop to diverge on, and keeps the boss an ordinary `Enemy_Kind`.

**`Pickup_Kind.Ammo` is retired, and the whole reserve with it.** `reserve_ammo`, `refill_weapon_reserve`, both `*_RESERVE_CLIPS` constants, the reload path's `min(clip_size, ammo_in_clip + reserve_ammo)` arithmetic and the empty-weapon state at `resource_indicator.odin:233` exist only to serve a mechanic the game decided not to have — `WEAPON_STARTING_RESERVE_CLIPS :: 69420` is that decision written as a joke instead of as code. Reload becomes an unconditional refill; the drop roll becomes a coin flip. Closes this map's standing pickup-kinds fog from the other side. New **Pickup** glossary entry, because a roster that shrank from three to two is exactly what a later reader restores by accident.

**The five family hues stay named constants, read by the preset table itself.** Hue means movement family — that is a rule the tenth kind has to obey, and `.Mite = {color = ENEMY_SWARMER_COLOR}` enforces it by construction where a comment beside the table only advises. A kind wanting a raw literal has to visibly refuse the convention to get one.

**Two tests, not one.** A "map is valid" test holds seven checks per `Map_Name`: one connected walkable region; `player_start` on floor; a reachable off-screen spawn ring; a cell-extent bound; rungs `1..N` with no gaps or duplicates; floor and wall colours non-zero; and `time_limit` either `<= 0` or greater than the point its last Spawn Trigger can still be spawning. A separate "preset table is well-formed" test holds the reach floor (`attack_range >= body_size/2 + 12`), the shared-inflation-envelope bound on non-boss kinds, and positive Gold. Separate because a Map and a preset fail for unrelated reasons and a merged test names the wrong culprit — and the envelope check matters more than the reach floor, since violating it costs a second collision map per frame rather than an enemy that can't reach you. It turns [Elite and affix tier](10-elite-and-affix-tier.md)'s authoring convention into a check.

**`time_limit` stays authored, `<= 0` stays legal.** [ADR-0022](../../../docs/adr/0022-map-rungs-are-gated-by-clears.md)'s `timeline_end + slack` reads as a derivation, but it is the number Map Selection shows the player and a menu displaying an arithmetic result cannot explain itself; deriving it also deletes the author's control over slack per rung, which is what the ADR was pricing. The untimed case survives as a legal choice no rung is expected to use — the honest expression of Cleared being derived from the timeline.

**One table for `weapon_family_kinds`, comment corrected — and the arrow-key hotkey retired.** The comment contradicts itself inside its own paragraph ([weapon.odin:820-825](../../../weapon.odin)): `[family][0]` *is* a fresh Run's starting weapon, and the table *is* the priced ladder. Retiring `cycle_weapon_kind`'s hotkey removes the second reader, so the split has no case left. It also removes a cheat that skips the entire priced ladder by holding an arrow key, which makes the Shop untestable at twelve weapons; `debug.odin` is where a deliberate cheat belongs. Amends [Shop and upgrades](../../shop-and-upgrades/map.md)'s standing fog item.

**Desert Dungeon is patched in the same change that lands the validity test.** A test authored red against the only map in the game is a test the follow-on will skip. Filling the 888 absent cells and bounding the extent is mechanical and is *not* the redraw — Desert Dungeon is still rebuilt when it is authored as a rung. What it buys is four new maps drawn against a check that was green before they existed.

**`Debug_Visualizer.Pathfinding` → `Flow_Field`, and the Swarmer ring is cut rather than ported.** A name outliving its mechanism is what [Elite and affix tier](10-elite-and-affix-tier.md) refused an "Elite" glossary entry over, and it costs one enum case. The new contour has no radius to draw — an enemy drifts along an iso-line — so the honest visualisation of it is the field, which `Flow_Field` now shows.

**`draw_tilemap` culls, and that closes [Art revamp](../../art-revamp/map.md)'s "per-frame transform-math at scale" fog.** 1704 tiles against ~225 visible, doubled whenever a menu is open, with two ambient layers about to sit on top. The tiles slice is world-indexed and `camera_visible_world_rect` exists, so it is a bounds test in the loop. The seam's siblings turn out to need nothing: ~17 pickups on the ground and 250 `draw_enemy` rects are small, and the cost that actually mattered — `move_actor`'s 852,000 rect checks a frame — was settled upstream. Culling is the last item under that fog.

**The flow field and the per-Run inflated collision map are both built on entering `Playing`, from the chosen Map.** The only moment both a Run and a Map exist. One named "a Map is now live" step rather than three things each remembering to initialise, and it makes spawn reachability available to the trigger at t=0. Rider: `update_enemies` and `movement_goal_point` test one shared `movement_style_collides` predicate rather than the same condition twice in two files.

**[ADR-0018](../../../docs/adr/0018-weapon-visual-identity-is-per-kind-not-per-family.md)'s countable rule binds `weapon_visuals` too**, with the same test `icon_test.odin` already applies to reach. The rule is about identity, not about which file the geometry lives in. Magic's own comment says its family vocabulary is "the flash and the tick burst, not streaks", so its missing countable dial has to come from that vocabulary rather than by borrowing Ranged's streak count. The Lightning Staff arrives countable for free — a hitscan beam is already a distinct draw path — so the work is the other three.

**One parametric enum↔identity-string helper, with an erroring read path.** Three sites defend against the same silent failure and the two halves of the round trip already sit in different files (`reflect.enum_from_name` in [main.odin:320](../../../main.odin), `enum_name_from_value` in [map.odin:147](../../../map.odin)). The wrapper is thin; the decision is the read side. **An unrecognised name means a deleted enum case and must surface as an error, not fall through to the zero value.** `main.odin:320` currently discards its `ok` into a silent skip — survivable for a menu default, not survivable for a spawn composition, where a dropped kind means a rung quietly spawns fewer enemies and Clears anyway.

**The boss's phase rotation lives inside the `Attack_Style` variant, not a parallel table.** A parallel table is indexed by every `Enemy_Kind` including the eight that cannot have phases, which moves the nil-field problem rather than solving it; and unlike the hit-volume table there is no second representation to keep honest, so that precedent does not transfer. One implementation constraint to check: a slice inside a package-scope `[Enemy_Kind]Enemy_Preset` literal needs static backing, so each rotation likely wants naming as its own package-level array — mechanical, but the kind of constraint that turns into "use a fixed array and a count" under pressure, capping phases at a number nobody chose.

**Three columns survive on Run_Start; the `max_kinds` derivation does not.** The columns carry the *family labels*, not the buttons — Ranged / Melee / Magic side by side is the screen's content, and stacking them turns a three-way choice into a list. What goes is layout maths reading `weapon_family_kinds` to size a panel whose drawn contents no longer relate to that table's length: the same "one table read two ways" fault just closed on the Shop side.

**The editor keeps a tuning surface, and persists it by writing Odin source.** The sliders being deleted are real and worth keeping; a slider pointed at a code table has nowhere to save to. `enemy.odin` stays authoritative and the editor exports into it, in its own `EditorMode`. Moving presets into a loadable data file was rejected: it undoes [ADR-0020](../../../docs/adr/0020-enemy-kind-is-the-authored-unit.md), and it hands the roster back to `core:encoding/json`'s union-variant guessing — confirmed broken here — exactly when the boss's phase rotation makes it a nested union. [ADR-0027](../../../docs/adr/0027-the-editor-generates-source-it-does-not-gain-a-data-format.md).

### The checklist, in landing order

**Stage 1 — the substrate.** Nothing else is runnable at roster density until this lands. Flow field flooded from the player, rebuilt on player cell change; delete `find_path`, `Path`, `MAX_SEARCH_NODES`, `get_neighbours`/`does_cell_collide`, `chase_to`, `assign_swarmer_slots`, `swarmer_surround_radius`, `Enemy.path`, `bullet.odin`'s `delete(enemy.path)`, `draw_path` (five files; check the test files for references). Cell-indexed solid set; `move_actor` and `tile_blocks_point` onto it, player included. Per-Run inflated collision map keyed by inflation radius. Both built on entering `Playing`. `movement_style_collides` as one predicate; `movement_goal_point` splits on it. Spawn placement gains the reachability lookup. Separation neighbour cap. `Flow_Field` rename; Swarmer ring cut from `Movement_Styles`.

**Stage 2 — persistence shape.** Before any content is written to disk, or `desert_dungeon.json` migrates twice. Shared enum↔identity-string helper with the erroring read. `Spawn_Composition_Entry` → `(kind, count)`, kind by name. Delete `Movement_Style_Save`/`Attack_Style_Save`, their four conversion procs, `map.odin`'s hooks, and `map_builder`'s duplicated DTOs and enemy `write_*_literal` procs. Rewrite `desert_dungeon.json`'s six composition entries. Account cleared set, identity-string keyed. `Spawn_Trigger`'s own unions keep their mirrors.

**Stage 3 — the roster.** `Enemy_Preset` table absorbing gold (one `int`, `enemy_gold_presets` dissolved) and colour; `ENEMY_MAX_HEALTH` deleted, `max_health` onto `Enemy` with the two draw-time reads and `enemy_body_size`'s caller following; `enemy_spawn_test.odin` and the debug overlays checked for the uniform 50. `MAX_ENEMIES` → 4096. `ENEMY_SIZE_MAX` → ~72. Five repalette constants, landing in the same commit as the preset rewrite. `Charger`. Per-kind `attack_range`, surface-to-surface. Preset well-formedness test. Editor Presets mode with Odin-literal export; `draw_spawn_composition_entry_ui` collapses to kind + count.

**Stage 4 — maps and the ladder.** `Tile.atlas_coords` deleted across all four places; editor Tiles mode collapses to a wall/floor toggle, losing `TILESET_COLS`/`ROWS`, `Palette_Cell` and `editor.selected_tile`. `Map` gains `rung` and the three theming fields on the same four-place path; `map_icon_colors` and its `hud.odin` consumer deleted, the swatch reading the wall colour. Editor map-level panel: New map, name, click-to-place `player_start`, `time_limit`, `victory_multiplier`, `rung`, six colour sliders, the ambient set. Map-validity test, seven checks. Desert Dungeon patched in the same change. Map Selection sorted by `rung` with locked/cleared states and a new lock glyph in `icon.odin`.

**Stage 5 — weapons.** Hit volumes per [ADR-0026](../../../docs/adr/0026-a-weapon-hits-only-what-it-touches.md): the unit-space polygon table and its containment test, `follow_through_time` carrying both fire modes, `draw_weapon`'s derived window deleted, `arc_degrees` gone from `Melee_Weapon` (three call sites, one save shape, one Upgrade), the swing arc onto `Weapon_Visual`, melee `range` re-tuned for the 12px pivot move, the second id counter and `Enemy` field reset at the Run boundary alongside `reset_bullets`. `Arc_Width` → **Reach** on `range`; `Clip_Size` → `Multiplicative`. Twelve icons and twelve `Weapon_Visual` rows, `icon_poison_staff` redrawn, the Magic row given a countable distinction, the countable test extended to `weapon_visuals`. `Bullet.id`/`Enemy.last_hit_bullet_id`. Hitscan `Spell_Kind` with its own one-frame draw path. `weapon_family_kinds` comment corrected, hotkey retired, Run_Start to one button per family with `max_kinds` deleted. The reserve deleted end to end, `Pickup_Kind.Ammo` with it. Documentation: `weapon.odin:57-72`, `CONTEXT.md`'s **Windup**/**Follow-through**/**Fire mode**/**Weapon readiness** entries, `weapon_test.odin`'s Follow-through assertions, and `resolve_weapon_action`'s `origin` comment all state retired rules.

**Stage 6 — boss and presentation.** `Attack_Style` Tell variant carrying the per-phase `(attack, tell seconds)` rotation; Tell countdown, committed action and phase index as runtime `Enemy` state, unpersisted. Boss preset with the guaranteed-drop field. Boss's own collision map and field, keyed by inflation radius. Boss Health indicator with a third `PLAYER_BAR_MAX_PARTICLES` array — resting on there being exactly one boss alive, which is [Boss model](05-boss-model.md)'s guarantee and worth naming at the array, since two bosses would silently share a particle set and read as a rendering bug. Ground layer named, with floor patches and Tell zones on it. Ambient pool with its own budget and two z-slots, never `game.particles`. Light wash inside `draw_world_contents`. `draw_tilemap` culling.

### Handed to the implementer, deliberately

Three questions whose consequence does not cross a file, named here so the follow-on knows they were seen: whether the hit-volume table lives in `icon.odin` with the geometry it mirrors or `weapon.odin` with the gameplay that reads it; whether the shared solid set hangs off `Tilemap` or sits beside the flow field; and whether the separation sample is the first N encountered or the nearest N, plus that constant's name.

### Not decided here

Balance numbers across the whole catalog, which stay this map's standing fog along with audio. The `Pickup_Kind` roster is no longer fog on the Ammo side — that half is answered by deletion — but whether new content later wants a *new* kind remains open, now with the rule that each kind added dilutes a roll the game only rolls once per death.
