# Web toolchain recipe

Type: research
Status: resolved

## Question

What is the exact Odin → wasm → Emscripten → raylib recipe for *this* repo, on the Odin version installed here (`odin version`)?

Facts the build sessions need, each verified against primary sources (Odin's own docs/source, raylib's, Emscripten's) and where possible against a throwaway compile of this repo:

- **wasm target**: `-target:freestanding_wasm32` vs `js_wasm32` — which one the Emscripten + raylib route wants, and why. What each gives up (`core:os`, `core:fmt` to stdout, the default allocator, threads).
- **raylib for web**: how the web `libraylib.a` is obtained or built (`PLATFORM_WEB`, GLES2/GLES3 backend), and which raylib version Odin's `vendor:raylib` bindings track — a mismatch is the classic failure.
- **Linking**: the `emcc` invocation — flags for the wasm object, `-sUSE_GLFW=3`, `-sASYNCIFY` or not, memory sizing, `-sEXPORTED_RUNTIME_METHODS`, `--shell-file`.
- **Odin ↔ JS**: how a foreign import declared in Odin reaches a JS function (`--js-library` with `mergeInto(LibraryManager.library, …)`, or `EM_JS` in a C shim). This is the mechanism the Save store will ride on, so pin the calling convention and string-passing shape (pointer + length? null-terminated?).
- **Runtime features on the target**: do `#load`, `core:encoding/json` (marshal + unmarshal), `core:reflect` (`enum_name_from_value` / `enum_from_name`, which ADR-0028's identity strings depend on), `core:math/rand`, and the temp allocator (`free_all(context.temp_allocator)` every frame) work on the chosen target? What replaces `log.create_console_logger` (`logger.odin:7`, needs `core:os`)?
- **Main loop**: `emscripten_set_main_loop` / `emscripten_set_main_loop_arg` from Odin; how `initialize_program`'s returned `runtime.Context` is kept for the callback; whether `rl.WindowShouldClose` is still meaningful.
- **GLSL**: raylib's web backend is GLES2 (or GLES3 with a flag) — what `data/shaders/blur.fs` (`#version 330`, `in`/`out`, `texture()`, `float[5]` literal) must become (`#version 100` + `varying`/`texture2D`, or `300 es`), whether `LoadShaderFromMemory(nil, fs)` still pairs with a compatible default vertex shader, and whether the two `LoadRenderTexture`s plus `BeginScissorMode` work on WebGL1 vs WebGL2.
- **Canvas sizing**: how the canvas tracks the browser viewport (CSS + `emscripten_set_resize_callback` / raylib's `WINDOW_RESIZABLE` on web), so `GetScreenWidth/Height`, read every frame in `main.odin:390`, sees the real size.
- **Known pitfalls**: Escape as raylib's default exit key inside a browser, `-sALLOW_MEMORY_GROWTH`, Safari WebGL quirks, `GetCharPressed` behaviour.
- **Reference implementations**: existing Odin + raylib + Emscripten templates worth copying from, with what each does differently.

Capture the findings as a Markdown file in the repo on a throwaway `research/web-toolchain` branch, and link it from this ticket's answer. Remember `git submodule update --init` before any compile attempt.

## Answer

Findings: `docs/research/web-toolchain.md` on branch `research/web-toolchain`.

Checked on `odin version` = `dev-2026-05-nightly:ea5175d`. `emcc` is **not installed** here, so the Odin half is verified by a throwaway compile of a copy of this repo and the `emcc` half is the proven template line, unverified locally.

- **Target**: `-target:js_wasm32 -build-mode:obj -define:RAYLIB_WASM_LIB=env.o`. Not `freestanding_wasm32`: that target has a nil temp allocator, no `log.create_console_logger` (compile fails at `logger.odin:7`), no `fmt` output, and panics on first RNG use. `js_wasm32` has all of those and costs one import module, `odin_env` (this repo needs 7 functions: `write rand_bytes time_now sin cos exp pow`), supplied by `odin.js` in the shell page's `Module.instantiateWasm`. `core:os` is unsupported on both; the 8 call sites (`read_entire_file` ×3, `write_entire_file` ×4, `exists` ×1) move behind the Save-store seam with `#+build js` / `#+build !js` files.
- **raylib**: use the shipped `$(odin root)/vendor/raylib/wasm/libraylib.a` — a PLATFORM_WEB/Emscripten/GLES2 build of 5.5 matching the 5.5 bindings. Upstream Odin master is already on 6.0 bindings and renames it `libraylib.web.a`; pin the Odin version in CI and read the path from `odin root`. `env.o` makes Odin emit raylib calls as plain undefined symbols that `emcc` resolves from the `.a` (Odin backend: any `.o`-suffixed foreign import path skips wasm import-module attributes).
- **Link**: `emcc -o build/web/index.html game.wasm.o libraylib.a -sUSE_GLFW=3 -sWASM_BIGINT -sWARN_ON_UNDEFINED_SYMBOLS=0 -sALLOW_MEMORY_GROWTH=1 -sINITIAL_HEAP=33554432 -sSTACK_SIZE=1048576 -sASSERTIONS --js-library web/shooter_env.js --shell-file web/index_template.html`. No `-sASYNCIFY`, no `--preload-file` (assets are `#load`ed), no `EXPORTED_RUNTIME_METHODS` needed. Custom shell is mandatory (it merges `odin_env` into the imports and drives the loop). `odin.js` is copied from `$(odin root)/core/sys/wasm/js/` at build time, never vendored.
- **Allocator**: Odin's default `wasm_allocator` and Emscripten's `sbrk` both grow linear memory and each assumes sole ownership; `main_start` must set `context.allocator` to a `malloc/calloc/realloc/free`-backed allocator (copy `emscripten_allocator.odin` from karl-zylinski/odin-raylib-web, zlib) *before* `runtime.init_global_temporary_allocator`. No global-scope allocations exist in this repo today; keep it that way.
- **Odin ↔ JS for the Save store**: a bare `foreign {}` block (no library name → wasm module `env`) of `proc "c"`s, implemented in `--js-library web/shooter_env.js` via `mergeInto(LibraryManager.library, {...})` with `__deps: ['$UTF8ToString','$stringToUTF8','$lengthBytesUTF8']`. Pinned shape: **pointer + explicit byte length, UTF-8, Odin owns every buffer** — `web_save_len() -> int`, `web_save_read(dst, cap) -> int`, `web_save_write(src, len)`. JS never allocates wasm memory, so nothing extra is exported.
- **Runtime features**: `#load`, `core:encoding/json` marshal+unmarshal, `core:reflect` enum name↔value, `core:math/rand`, `core:log`, `vendor/ui`, and the per-frame `free_all(context.temp_allocator)` all compile on `js_wasm32` with zero changes (proven). `log.create_console_logger` exists on js (`console_logger_js.odin`), so `logger.odin` needs no change (the template swaps in a `puts` logger only to avoid doubled newlines).
- **Main loop**: `main :: proc()` moves to `main_desktop.odin` (`#+build !js`); `main_web.odin` (`#+build js`) exports `main_start` (allocator swap, then stores the `runtime.Context` that `initialize_program` already returns in a file-private global), `main_update` (restores `context`, runs `update_game(); draw_game(); free_all(temp)`, returns true), `main_end`. The page calls `_start()` (runs `@(init)`, no `main` on web) then `main_start()` and drives `main_update` with `requestAnimationFrame`. `rl.WindowShouldClose` is `emscripten_sleep(16); return false;` on web — `program_should_exit` returns false under `when ODIN_OS == .JS`. Never `SetTargetFPS` on web. Clamp `GetFrameTime` in the web entry: a hidden tab stops rAF and the next dt is the whole gap.
- **GLSL**: shipped lib is GLES2 → WebGL1 → the default vertex shader is `#version 100` with `varying fragTexCoord/fragColor`. `LoadShaderFromMemory(nil, fs)` still pairs with it, so only `blur.fs` changes: a second file `blur_es100.fs` (`#version 100`, `precision mediump float;`, `varying`, `texture2D`, `gl_FragColor`, and the `float[](…)` literal unrolled — GLSL ES 1.00 §4.1.9 forbids array initialisers), selected with `when ODIN_OS == .JS` at the `#load`. Two `LoadRenderTexture`s and `BeginScissorMode` are WebGL1-core; NPOT render textures and the 2046×1200 atlas get `CLAMP_TO_EDGE`/no mipmaps automatically on WebGL1, which matches what `renderer.odin:141` already sets and nothing relies on `REPEAT`.
- **Canvas**: nothing to write. With the existing `FLAG_WINDOW_RESIZABLE`, `rcore_web.c` registers a window resize callback that sets the canvas to `window.innerWidth/innerHeight` and updates `GetScreenWidth/Height`; it fires once in `InitWindow`, so the saved size is overwritten before the first frame. Canvas must be `id="canvas"`, page CSS `margin:0; overflow:hidden`. Backing store is CSS pixels (no HiDPI on web).
- **Pitfalls**: Escape is consumed by the browser only in fullscreen/pointer-lock; `SetExitKey(.KEY_NULL)` stands. `GetCharPressed` rides the DOM `keypress` event — the template's `onkeydown="event.preventDefault()"` on the canvas would kill it; only the editor reads chars today. `ALLOW_MEMORY_GROWTH` is safe (no cached heap views). Safari untested.
- **Test files**: `core:testing` does not compile on `js_wasm32` (this nightly and upstream master: `testing/logging.odin` calls `log.do_level_header`, absent from the js logger). `odin build` compiles every `*_test.odin`, so all 29 game test files plus `vendor/ui/layout_test.odin` and `vendor/ui/ui/ui_test.odin` need `#+build !js`.
- **Reference**: karl-zylinski/odin-raylib-web (last commit 2026-07-31; same author as `vendor/atlas-builder`) is the template to copy the allocator, shell and entry shape from; it differs only in using `--preload-file assets`, an extra `web_window_size_changed` export, `libraylib.web.a` (newer Odin), and a `puts` logger.

**Biggest risk**: the link step is unverified — no `emcc` on this machine. Second: the pinned submodule commits (`vendor/ui`, `vendor/atlas-builder`) are not on their remotes, so `git submodule update --init` fails in a fresh worktree and will fail in CI until they are pushed.
